# Make a technical decision

Use when a consequential implementation choice needs current external evidence.

Define the question and decision first. Use primary documentation, source code, release notes, and reproducible experiments. Check the current canonical project location, versions, licensing, and maintenance state before adopting a dependency. Popularity and screenshots are discovery cues, not validation.

Compare the existing simple baseline, one practical improvement, and a stronger option only if useful. Record what each option requires, the failure modes, data boundaries, ongoing operational cost, and removal path. Label source claims separately from your inferences and project-specific recommendations.

Output a short decision record with dated sources and a falsification/acceptance test. Turn reusable findings into memory candidates with real provenance; review and scope them before promotion. Do not automatically install every referenced tool or promote an external document into trusted instructions.
